# Model Inventory

Model data for planning documents that depend on model, effort level, and context window. Gives per model: generation rung, Items, context window, supported effort levels, and standard-tier USD prices per 1M tokens (`In USD`, `Cache USD`, `Out USD`).

This file holds data only. Part of `@skills:llm-tools` (same folder as the source JSONs). Planning techniques that use it (`@skills:write-documents`):
- `PROMPTS_GUIDES.md` Section 1g - prompt count, checkpoints, scope guard, context fit per model
- `TASKS_GUIDES.md` - HWH estimation, task and STRUT step sizing, AWH estimation
- `PROMPTS_RULES.md` PRMT-SC-05 - verification of prompts files against this data

Sources (canonical, update this file when they change):
- `skills/llm-tools/model-registry.json` 1.15.0 (2026-11-18) - context window, supported effort levels, `uc_class`, `release_date`, `eci_score`, `eci_ci`, `generation`, `generation_evidence`, `higher_than`, `items`, `scope_guard`, `inventory_note`

## 1. Definitions

- Generation `G[nn]`: ordinal rung of provable reasoning depth. `G01` = lowest listed model; higher = more may stay implicit in a prompt. Assigned once, never regraded. `G[nn]*` = estimate, replaced by evidence when it arrives. Equal rung = equal prompt shape, not equal quality
- ECI Score: Epoch Capabilities Index score (`eci_score` in `model-registry.json`, 1 decimal); `-` = no Epoch score. Informational only, does not set the rung unless E3 applies; the 95% interval stays in Notes
- Items: numbered instruction items one implementation prompt may hold so that all complete without skips. `[n]m` = measured from the observation ledger; unmarked = default from the rung (Section 2)
- HWH (Human Work Hours): hours a skilled human expert needs for the same work unit without AI. Model-independent task size; one prompt carries at most 1 HWH
- Context: total context window (input plus output) in thousands of tokens (K), computed as `floor(context_window / 1000)` from `model-registry.json`. Input read per prompt stays at or below 50% of Context
- Efforts: supported effort levels `L` Low, `M` Medium, `H` High, `X` XHigh, `MX` Max; `-` = no effort parameter. Choosing an unlisted level is a PRMT-SC-05 violation
- In USD / Cache USD / Out USD: standard-tier USD price per 1M input, cached input, and output tokens (`-` if not published or unsupported)
- Value: price score within the rung, from 1.0 (most expensive of the rung) to 5.0 (cheapest), on the log scale of the cost `0.8 * In USD + 0.2 * Out USD`; shown as five star symbols (full, half, empty; nearest 0.5) and the score, e.g. four full stars and one half star for `(4.4)`; `-` = one model in the rung, equal costs, or no price. Compares price only, not quality; recomputed on every update
- Released: release date of the model, `YYYY-MM-DD`, or `YYYY-MM` when only the month is known; value of `release_date` in `model-registry.json`, re-checked against the vendor page in every update run; `-` = no source states a date (only Devin-only rows of Section 3.2)
- Notes: the edge that set the rung, `UC-n` (Universal Class: 1 Apex, 2 Flagship, 3 Balanced, 4 Efficient), Epoch score with 95% interval, status, `scope guard strict`, `CSV rows` (confirmed reliable rows for 7-column CSV extraction per effort), adaptive Medium warning, `squeezed by`, `unplaced`

## 2. Value Derivation

Generation edges (`x > y` = x provably higher than y; the rung is the longest chain of edges below the model):
- E1 vendor tier: same provider and point version, higher class (strict). Across point versions only from the vendor's model-selection guidance (`E1m`, recorded with source and quote)
- E2 successor: same provider, class, and series, later release: rung at least the predecessor's. E3 benchmark: Epoch 95% intervals do not overlap (strict)
- E4 in-house observation naming both models on the same task (strict, `E4m`, overrides E3). E5 sibling tie: unscored model = scored sibling of the same point version and class
- E6 estimate (`*`): unscored model without a sibling tie: rung of the nearest-class sibling minus the class distance, floor `G01`; no sibling = `G01*` `unplaced`
- New models insert between frozen rungs; no free integer = `squeezed by X`. Silence of the named source = tie, never a judgment edge

Prompt shape (read from the row; compute nothing else):
- Effective rung: `H`, `X`, `MX` = Generation; `M` = Generation, except adaptive-thinking models (Notes `adaptive`) one rung lower; `L` one lower; `-` two lower
- Explicitness by effective rung: `G10+` goal-level (0.5 items per outcome unit), `G07-G09` outcome plus named files (1), `G04-G06` step-level (2.5), `G01-G03` keystroke-level (4)
- Items default by effective rung: `G10+` 8, `G07-G09` 6, `G04-G06` 5, `G01-G03` 4. Items 8: max 6 files, checkpoint every 3 prompts; Items 6: 3 files, every 2; Items 5 or less: 2 files, after every prompt
- `prompt_count = max(ceil(expanded_items / Items), ceil(files / max_files), ceil(task_HWH / 1))`
- Notes `scope guard strict`: every prompt states "Do ONLY the numbered items below. Do not refactor, rename, add tests, or touch files not listed. Report any item you could not complete as NOT DONE". Items unchanged
- Cost per prompt: `(0.8 * In USD + 0.2 * Out USD) * tokens / 1M`. Devin prices are the prices of the Devin models page (Section 3.2); no Devin multipliers

## 4. Maintenance

- Section 3.1 and the `Top rung` line are generated from the registries; hand edits are overwritten. Section 3.2 is generated from the Devin models page of the run; the rung of a Devin-only model is set once from a vendor statement and kept in the run's `Generation-Edges.json` `devin_only[]`
- Every registry update: new models receive `release_date`, `uc_class`, Epoch score and interval, and edge-case outcomes from vendor pages, then the layering inserts their rungs. Existing rungs never move; only `*` estimates may change to measured
- Manual edges (`higher_than`) carry model, kind, source, access date, and quoted statement; an edge without them, or one that closes a cycle, stops the update
- Items: `observed.items` from the ledger replaces the default after 3 sequences; a skip observation lowers it to the largest fully completed value. Items never changes Generation
- Scope guard: `scope_guard: strict` is set with the FAILS or ledger reference in `inventory_note`
